# V6.7.3 — Intercom du site, jukebox à bord, sons

*Date : 02/11/2026*  
*Tag : `v6.7.3` (cible : `main`)*

Modifications 20, 21, 3 et 22 de [PROPOSITIONS.md](https://github.com/StudioRbx/T.A.R.D.I.S/blob/main/docs/PROPOSITIONS.md). Écrit sans accès à Studio : **à tester en jeu**.

### 1. Intercom « faille spatio-temporelle » (modification 20)
- La **première matérialisation visible** de chaque TARDIS pendant la session (posé après une remat, ni camouflé, ni porté) est publiée sur un nouvel événement serveur, `ServerStorage › TardisEvenements` (`"FailleSpatioTemporelle"`, avec le TARDIS, le lieu, la position, le mode et l'heure).
- Nouveau Script **`TardisPontFondation`** (ServerScriptService, un seul exemplaire) : il fait l'annonce.
  - Si **`Config.Intercom.Cible`** contient le chemin d'un objet de l'OS Fondation (par exemple `"ServerScriptService.OSFondation.OSAppsServeur.Intercom"`), il lui transmet le message : BindableEvent (`:Fire`), BindableFunction (`:Invoke`) ou ModuleScript (fonction `annoncer`, `Annoncer`, `Annonce` ou `Broadcast`).
  - Sinon, ou si l'OS refuse, **annonce intégrée** : bandeau d'alerte en haut de l'écran de tous les joueurs (bandes rouges et jaunes qui défilent, texte qui s'écrit comme sur un téléscripteur, 10 s), alarme (son `Intercom`, sinon trois bips d'alerte), et message système dans le chat.
- Ensuite, les pilotes reçoivent un **rappel toutes les 10 min** (`Config.Intercom.RappelMinutes`).
- Textes réglables : `Titre`, `Message`, `Rappel`. `Actif = false` coupe tout.
- **Pourquoi `Cible` est vide :** je n'ai pas accès au code de l'OS Fondation depuis ici. Dis-moi le nom et le type de l'objet qui fait les annonces dans `OSAppsServeur`, et je le branche.

### 2. Jukebox audible seulement à bord (modification 21)
- La musique est maintenant un **son local** (et non plus un son positionné sur le rotor) : seuls ceux qui sont à bord l'entendent, avec un **fondu** quand on entre ou sort. Elle se coupe hors tension.
- **Playlists par catégorie** : une piste avec `categorie = "Action"` rejoint la playlist **Action**, lue en **ordre aléatoire et enchaînée**. Bouton « ► Playlist Action » dans l'outil Jukebox de la tablette.
- **`Config.Jukebox` est vide** : je ne peux ni écouter ni vérifier des identifiants de musique d'ici. Format : `{ nom = "…", id = 1234567890, categorie = "Action" }`. Prends des sons publics de la Toolbox (onglet Audio) ou ceux du jeu.

### 3. Sons (modifications 3 et 22)
- **Bug corrigé :** `Cloitre` et `Reparation` étaient joués par les systèmes (pannes, réparations, régénération à bord, paradoxe) mais n'étaient **jamais préparés** par le serveur : on ne les entendait pas, même placés dans `TardisAssets › Sons`. Ils sont maintenant préparés dans la salle et dehors.
- **`Config.Sons`** : chaque son peut être déclaré par son identifiant ; il est créé au démarrage s'il n'existe pas déjà (un Sound placé à la main reste prioritaire). Deux **replis intégrés à Roblox** sont déjà remplis : `Chute` (vent de chute libre) et `Impact` (atterrissage, ralenti). Les autres valent 0 en attendant de vrais sons.
- Le **diagnostic** du démarrage compte les sons sans doublons (plusieurs modes partagent les mêmes) et **liste les sons absents**.

### Technique
- `Config.Intercom`, `Config.Sons` ; `Config.Jukebox` accepte `categorie`.
- Serveur : section Intercom de `TardisExtras` (attribut `FailleSignalee`), nouveau Script `TardisPontFondation`, RemoteEvent `ReplicatedStorage › TardisAnnonceSite` ; `TardisServeur` crée les sons de `Config.Sons` et prépare `Cloitre` / `Reparation` ; action `Jukebox` avec `liste`.
- Client : nouveau module `TardisExtrasClient › Intercom` ; jukebox de `Ambiance` réécrit ; outil Jukebox de la tablette avec les playlists.
- `Config.Version = "6.7.3"`.
