# V6.9.17 — Maps en Streaming

*Date : 07/11/2026*  
*Tag : `v6.9.17` (cible : `main`)*

Correction demandée après l'import de la structure dans une map en **Streaming** (Zone obstruée) : ni le menu (T) ni la tablette (Y) ne s'ouvraient. Avec `StreamingEnabled`, le client ne reçoit que les pièces proches de lui ; quand les pièces de l'intérieur sont posées directement dans le dossier `INTERIEURE`, celles qui sont loin n'arrivent jamais et les scripts du joueur attendent l'intérieur sans fin. Vérifié en jeu dans la map de test et par simulation.

### L'intérieur rangé dans un Model Persistent
- Au démarrage, **si la map est en Streaming** et que les pièces de l'intérieur sont directement dans `INTERIEURE` (`Portail` ou `Rotor` en enfant direct), le serveur les range dans un **Model `<TARDIS>_INTERIEURE`** (par exemple `TARDIS_1_INTERIEURE`) en **`ModelStreamingMode = Persistent`**, à l'intérieur du dossier. Un Model Persistent arrive **en entier** chez chaque joueur, dès son arrivée.
- Le repère du Model est le centre de l'ancienne boîte du dossier : les positions calculées à partir de l'intérieur ne changent pas.
- Un avertissement dans l'Output le signale. Pour ne plus le voir, faire la même chose une fois dans Studio et enregistrer.
- **Sans Streaming** (comme DEVMAP), rien ne change : le dossier reste l'intérieur. L'ancienne organisation (un Model dans `INTERIEURE`) est toujours lue telle quelle.

### Diagnostic au démarrage
- En Streaming, la ligne du diagnostic finit par **« streaming : ok »** quand l'intérieur et l'extérieur sont des Models Persistent, sinon **« streaming : à régler »**, avec un avertissement qui nomme ce qu'il faut changer.

### Import de la structure
- `outils/importer_structure.luau` (avec `PLACER = true`) range lui aussi l'intérieur dans le Model Persistent quand la map est en Streaming, avant de le mettre à sa place.

### Technique
- `TardisConfig` : `Config.Version = "6.9.17"` ; `rangerPourLeStreaming(def, dossierInt)`, appelé par `Config.modeles` côté serveur seulement.
- `TardisDiagnostic` : vérification `ModelStreamingMode` de l'intérieur et de l'extérieur quand `workspace.StreamingEnabled`.
- Aucune nouvelle action réseau.

### Simulations
- `outils/simulation/sim_v6917.py` : **23 tests sur 23** (rangement côté serveur en Streaming, nom, mode Persistent, contenu, repère, avertissement unique, second appel identique ; rien sans Streaming, rien côté client, ancienne organisation inchangée ; diagnostic « ok » et « à régler » ; importeur).
- Simulateur : `workspace.StreamingEnabled` et `Model.ModelStreamingMode` ajoutés.
- Toutes passent : **1 821 vérifications**, analyse statique : 0 remarque.
