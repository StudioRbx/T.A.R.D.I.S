## V6.0 — Trois TARDIS (13/10)

### Changement d'architecture (le plus profond depuis la V3)
- **Il n'y a plus un seul TARDIS, mais trois** : `TARDIS_1`, `TARDIS_2` et `TARDIS_3`.
- **Nouvelle hiérarchie :**
  ```
  Workspace
  └─ TARDIS (Folder)
     ├─ TARDIS_1 (Folder)
     │  ├─ EXTERIEURE (Folder) › <Model extérieur, PrimaryPart = Racine>
     │  └─ INTERIEURE (Folder) › <Model intérieur>
     ├─ TARDIS_2 …
     ├─ TARDIS_3 …
     └─ TARDIS_DESTINATIONS (Folder)
        ├─ ACCORDE  → atterrissage normal
        └─ REFUSE   → urgence uniquement
  ```
  Le script prend le premier Model de chaque dossier, quel que soit son nom.
- **Configuration par TARDIS :**
  ```lua
  Config.Pilotes     = { UserIds = { ... }, UniquementUserIds = true } -- pilotes de TOUS les TARDIS
  Config.Techniciens = { UserIds = {} }                                -- techniciens de TOUS les TARDIS
  Config.Tardis = {
      { Nom = "TARDIS_1", Pilotes = { UserIds = {} }, Techniciens = { UserIds = {} } },
      { Nom = "TARDIS_2", ... },
      { Nom = "TARDIS_3", ... },
  }
  ```
- **Chaque TARDIS est indépendant** : portes, console, menu, tablette, vol, outils, rôles temporaires, bannissements, sauvegarde. Un pilote de TARDIS_2 ne contrôle que TARDIS_2.
- **Un seul exemplaire de chaque script à installer** : au lancement, chaque script **se clone lui-même** pour les TARDIS 2 et 3 (`Config.demarrerPourChaqueTardis`, attribut `Tardis`). Les RemoteEvents et canaux sont suffixés (`TardisCommande_TARDIS_x`, etc.).
- **Partagé entre les trois** : destinations, sons, tenues, balise de détresse (les pilotes des 3 TARDIS sont prévenus) et effets visuels.
- **Les zones `ACCORDE` et `REFUSE` remplacent les sous-dossiers « Zone accessible » et « Zone restreinte ».**
- Au démarrage : 9 lignes « prêt » (serveur, extras et systèmes × 3 TARDIS).
- 14 scripts modifiés (`TardisUI` et les `Shut` inchangés).

### V6.0.1 — Correctif : aucun portail ne marche
- **Cause :** `TardisServeur` cherchait `TARDIS_DESTINATIONS` à la racine du Workspace, alors qu'il est maintenant dans le dossier `TARDIS`. Il attendait indéfiniment et ne créait jamais sa RemoteEvent, ce qui bloquait tout le reste en cascade.
- **Correction :** le dossier est accepté **à la racine ou dans `TARDIS`** (`Config.dossierDestinations`). Scripts : `TardisConfig`, `TardisServeur`, `TardisExtras` et `TardisTablette`.
- Commandes de vérification fournies pour la barre de commande de Studio (hiérarchie, PrimaryPart, Portail extérieur et intérieur, Rotor, positions).
- Conseils : intérieurs à au moins 200 studs les uns des autres, un seul objet nommé `TARDIS`, des Folders (et non des Models) pour `TARDIS_x`, et désactiver les scripts `Power` des écrans et `Move` du rotor du kit.

### V6.0.2 — Lecture tolérante des IDs
- `Pilotes = { UserIds = { ... } }` **et** `Pilotes = { ... }` sont tous deux acceptés.

### V6.0.3 — Portes de TARDIS_1
- **Scripts `Shut` réécrits** (gauche et droite, à mettre dans chaque TARDIS) : les portes de TARDIS_1 s'ouvrent de nouveau avec E.
- TARDIS_2 et TARDIS_3 : il manquait le `Portail` intérieur, et `Rotor` et `Console` étaient dans un sous-Model `Model` (il faut le dégrouper).

### V6.0.4 — Passage par la porte fiabilisé
- **Bug :** on restait bloqué dans le décor deux fois sur trois en entrant.
- **Corrections (`TardisPortail` et `TardisExtrasClient`) :** si le point d'arrivée tombe dans un mur, un battant ou la console, le personnage avance par petits pas jusqu'à une place libre, et sa vitesse est remise à zéro.
- **Conflit propre à la V6 :** les 3 exemplaires du script utilisaient les mêmes liaisons d'image (`TardisPassage`, `TardisVue`). Chacun a maintenant les siennes.
- Conseil : poser une Part `Arrivee` dans l'intérieur.

### V6.0.5 — Correctif : T et Y ne répondent plus
- `TardisTablette:199` et `TardisMenu:78` appelaient `UI.degradeEntete()`, absente d'un ancien `TardisUI` → **remplacer `TardisUI`**.
- `TardisExtrasClient` : la `Lampe` du nouveau modèle est un **Model** (« CFrame is not a valid member ») ; une pièce à l'intérieur est utilisée.

### V6.0.6 — Zone REFUSE
- Une destination du dossier **REFUSE** demandée en mode normal : la matérialisation normale commence, est **repoussée à mi-parcours** (« ZONE REFUSÉE : MATÉRIALISATION REPOUSSÉE », démat d'urgence courte), puis **1,5 s plus tard, rematérialisation d'urgence au même endroit**.
- En urgence directe, il atterrit du premier coup. L'ancien repli vers la destination accessible la plus proche ne se produit plus.

### V6.0.7 — Coupure automatique
- **Coupure après 15 voyages consécutifs** (au lieu de 5) : `Config.Systemes.VoyagesAvantCoupure = 15`.
- **Bug corrigé :** l'invite « Redémarrer le système » (E maintenu 10 s) était cachée par l'invite On/Off du même levier. Pendant le redémarrage requis, seule l'invite de maintien est affichée.

### Ajout : mode de voyage (Réglages, préférence par joueur)
- **Automatique (par défaut)** : choisir la destination, puis DEMAT. Le TARDIS entre dans le vortex, REMAT affiche « Auto dans 15 s », puis il se matérialise seul. Un appui sur REMAT part tout de suite ; sans destination, DEMAT le rappelle.
- **Manuel** : DEMAT d'abord. Les destinations restent verrouillées tant que le TARDIS est posé et se débloquent dans le vortex ; puis REMAT à la main.
- Le menu rapide (T) suit la même règle que la tablette.
- **`PATCH_NOTES_COMPLET_V6.5.md`** (format Discord), regroupé par thème.

### V6.5.2 — Performances : lag à l'ouverture du panneau (17/10)
- **Cause :** la tablette cherchait `TARDIS_DESTINATIONS` dans **tout le Workspace**, pour chaque destination et à chaque image. Sur une map de dizaines de milliers d'objets (plus de 5 Go de mémoire), cela faisait des centaines de milliers de vérifications par image.
- **Corrections :**
  - dossier des destinations **cherché une seule fois, puis mémorisé** ;
  - lumières des salles : liste mémorisée, et une salle n'est traitée que si la caméra est à moins de **350 studs** ;
  - anomalies : le serveur ne parcourt plus tout le Workspace toutes les secondes, seulement les pièces autour du TARDIS ; recherche des entités toutes les 10 s (au lieu de 5).
- Scripts : `TardisConfig`, `TardisEffets` et `TardisExtras`.

### V6.5.3 — Retrait de TARDIS_2 et 3, et crash du ciel
- Pour supprimer TARDIS_2 et TARDIS_3 proprement, il faut **mettre leurs lignes en commentaire** dans `Config.Tardis`. Sinon, leurs scripts attendent indéfiniment (« Infinite yield »).
- **Bug corrigé `TardisServeur:366` :** la boucle de rotation dans le ciel pouvait se réveiller juste après le début de l'atterrissage, planter, voire replacer le TARDIS dans le ciel pendant une image. Elle s'arrête maintenant proprement.

### V6.5.4 — Stabilisateur et secousses de caméra
- Le stabilisateur ignorait les secousses de caméra pendant les démat et remat. Désormais :

| | Stabilisateur actif | Stabilisateur coupé |
|---|---|---|
| Voyage normal | aucune secousse | secousses normales |
| Voyage d'urgence | 30 % | fortes |

### V6.5.5 — Urgence stabilisée
- Urgence avec stabilisateur : secousses à **5 %**.
- La **gravité folle** (le joueur qui glisse tout seul) est **annulée par le stabilisateur**.
- Scripts : `TardisEffets` et `TardisExtrasClient`.

### V6.5.6 — Son d'alarme
- Quand l'alerte est active, le son **`Alarme`** (`TardisAssets › Sons › Alarme`) joue en boucle dans la salle de contrôle. Il s'arrête avec l'alerte, hors tension ou à la destruction, suit le volume de la tablette et garde la portée du son d'origine.

### V6.5.7 — Régénération refondue (18/10)
| Demande | Fonctionnement |
|---|---|
| Équipe | Seuls les joueurs de l'équipe **« Le Voyageur »** se régénèrent (pilotes ou non) ; un changement d'équipe est pris en compte tout de suite |
| Nombre | **Infini** (`Nombre = 0`) |
| Invulnérabilité | Pendant la régénération, bouclier invisible et santé maintenue au maximum : rien ne l'interrompt |
| Apparence | Un des **avatars sauvegardés du compte** (permission demandée une fois), jamais deux fois de suite le même ; sinon une tenue de `Config.Tenues` |
| Soin | 100 % à la fin, plus **+100 PV pendant 5 min** (non cumulable) |

```lua
Config.Regeneration = { Equipe = "Le Voyageur", Nombre = 0, Duree = 5, BonusPV = 100, BonusDuree = 300, TenuesDuCompte = true }
```
- Scripts : `TardisSystemes`, `TardisExtrasClient` et `TardisConfig`.

### V6.5.8 — Régénération après `:kill`
- **Bug :** `:kill` (panneaux d'admin) casse toutes les articulations : le corps tombait en morceaux et seule la tête prenait la nouvelle apparence.
- **Correction :** vérification du corps (cou, épaules, hanches, articulation racine). S'il est disloqué, **un corps neuf est reconstruit sur place** avec le nouvel avatar. Conséquence : l'inventaire repart de zéro, comme après une mort.

### V6.5.9 — Six idées de la série
- **Régénération refusée** : une fenêtre de 3 s (« L'énergie de régénération monte ») avec le bouton Refuser ; un refus entraîne la vraie mort et remet le compteur à zéro.
- **Régénération dans le TARDIS** : étincelles, tremblements, alarme et cloche du Cloître, **−400 d'intégrité**.
- **Compteur** : outil **Régénérations** de la tablette (heure, joueur, numéro, lieu, refus et vraies morts ; 40 entrées).
- **Lien Time Lord** (désactivé par défaut, activable par un pilote) : les autres Voyageurs ressentent la régénération (flash, secousse, nom et distance).
- **Membre qui repousse** (5 min après, au bout de 2,5 s, R6).
- **5 animations** : Classique, Volcan, Douce, Tourbillon et Colonne.
- Réglages : `Style`, `ChoixRefus`, `DelaiChoix`, `DegatsTardis` et `RepousseDuree`. Les heures du journal sont en UTC.
